# Provenance and originality

## First-party code

Everything under `apps/`, `packages/`, `scripts/`, `tests/` and `docs/` was written for this
repository from its product requirements, documented public APIs and general engineering
knowledge. No source code, tests, assets, prompts, UI layouts or documentation from any earlier
implementation were read, copied, translated or adapted during development. The development
environment was configured to deny read access to the earlier project's directories, and that
denial was tested.

Two items came from tool scaffolding rather than being hand-written:

- `apps/web/angular.json`, `tsconfig*.json` and `src/main.ts` started from the Angular CLI
  `ng new` output (Angular's own MIT-licensed templates) and were then modified.
- `package-lock.json` is generated by npm.

## Third-party components

Third-party packages keep their own licences. `npm run audit:release` writes a CycloneDX SBOM to
`reports/sbom.json` and fails on any licence outside the allow-list. MPL-2.0 is accepted only
for development tools that are not distributed (`lightningcss`, `axe-core`). The Angular build
writes the licences of bundled packages to `apps/web/dist/3rdpartylicenses.txt`. Ship that file
with any distribution of the web build.

Runtime dependencies: `fastify`, `zod`, `@anthropic-ai/sdk` (loaded only when the Anthropic
provider is enabled), and Angular with `rxjs` and `tslib` in the browser bundle.

## What the automated checks do — and do not — prove

`npm run audit:release` checks:

- local-only files (planning notes, machine settings) are not tracked;
- no tracked file references machine-specific absolute paths or the earlier project's paths;
- no obvious secrets, symlinks or git submodules;
- dependency licences, with an SBOM;
- known vulnerabilities (high/critical in runtime dependencies fail the check);
- the built web app has no inline scripts.

These checks show that nothing was imported **by path or by copy into this tree**. They cannot
prove legal originality, and a missing comparison with the earlier source is not a passed test.
No similarity analysis against the earlier implementation has been run, because doing so would
require access to that source, which this project deliberately avoids. If an independent
originality review is needed, it should be done separately, by someone with authorised access to
both codebases.
